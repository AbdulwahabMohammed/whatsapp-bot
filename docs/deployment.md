# خطوات النشر على بيئة الإنتاج

تحتاج عملية نشر البوت إلى بعض الإعدادات المسبقة على الخادم المستهدف:

1. **تهيئة المتغيرات البيئية**
   - انسخ ملف `.env.example` إلى `.env` واملأ القيم المناسبة لمفاتيح OpenAI وقاعدة البيانات.
   - يمكن تحديد الحد اليومي للتوكنات عبر المتغير `DAILY_TOKEN_LIMIT`.
2. **تثبيت الاعتمادات**
   ```bash
   npm install --production
   ```
3. **تهيئة قاعدة البيانات**
   ```bash
   node src/initDb.js
   ```
   ينشئ هذا الأمر جميع الجداول المطلوبة بما فيها جدول `usage_stats` الخاص بتتبع استهلاك التوكنات وجدول `conversation_stats` الذي يسجل أزمنة الاستجابة لكل محادثة.
4. **تشغيل البوت كخدمة**
   يمكن استخدام أدوات مثل `pm2` أو `systemd` لتشغيل الأوامر التالية في الخلفية:
   ```bash
   npm run whatsapp
   npm run worker
   ```
   **تنبيه:** ينبغي تشغيل عملية واحدة فقط تتولى الاتصال بواتساب لكل حساب.
   استخدام الأمرين معاً بنفس بيانات الاعتماد يؤدي إلى انقطاع الاتصال برسالة
   "Stream Errored (conflict)" من مكتبة Baileys.
5. **تشغيل واجهة الإدارة**
   ```bash
   npm run admin
   ```
   يشغِّل هذا الأمر الخادم باستخدام الدالة `startAdminServer()`.
   عند أول تشغيل سيُنشِئ سكربت `initDb.js` حسابًا باسم `admin` مستخدمًا كلمة
   المرور الموجودة في المتغير `ADMIN_PASSWORD`. بعد تشغيل الخادم توجّه إلى
   `/login` وسجل دخولك بهذا الحساب. يمكن تفعيل المصادقة الثنائية لاحقًا من
   صفحة "Profile" داخل لوحة التحكم إذا رغبت بذلك، كما يمكن تعطيلها من نفس الصفحة.
   تأكد أيضًا من تحديد المتغير `ADMIN_PORT` لاختيار المنفذ المناسب.
6. **مراقبة السجلات والتأكد من الاتصال بواتساب**
   عند أول تشغيل سيُطلب مسح رمز QR لربط الحساب.
   يستخدم البوت آلية إعادة اتصال تدريجية في حال انقطاع الاتصال تصل إلى
   `MAX_RECONNECTS` محاولة قبل التوقف عن المحاولة.
7. **السجلات**
   - تُحفظ ملفات السجلات في مجلد `logs/` بصيغة JSON، ويتم تدويرها يوميًّا باستخدام الملفات `app-%DATE%.log` لرسائل المستوى `info`
     وما فوق، بينما تُخزن الأخطاء في ملفات منفصلة `error-%DATE%.log`.
   - يُضغط كل ملف عند التدوير مع الاحتفاظ الافتراضي بآخر 14 ملفًا للأحداث العامة و30 ملفًا للأخطاء وحد أقصى 20 ميغابايت للملف.
   - يمكن تغيير مستويات التسجيل وسعة الاحتفاظ عبر المتغيرات `LOG_LEVEL` و`LOG_FILE_LEVEL` و`LOG_MAX_SIZE`
     و`LOG_MAX_FILES` و`LOG_ERROR_MAX_FILES`، كما يمكن التحكم في سجل الطرفية أثناء التطوير عبر `LOG_CONSOLE_LEVEL`.

8. **مقاييس Prometheus**
   - عند تشغيل واجهة الإدارة يتوفر المسار `/metrics` الذي يعرض إحصاءات Prometheus.
   - يمكن إضافة المهمة التالية في إعدادات خادم Prometheus لجمع المقاييس:
     ```yaml
     scrape_configs:
     - job_name: 'whatsapp-bot'
        static_configs:
          - targets: ['localhost:3001']
            metrics_path: /metrics
    ```
    تأكد من مطابقة المنفذ مع قيمة `ADMIN_PORT` في ملف البيئة.
   - يشمل البوت مقياس `queue_length` الذي يعرض عدد الرسائل المنتظرة في طابور المعالجة.

9. **لوحة الإحصاءات**
   - تتوفر صفحة `/stats` في واجهة الإدارة لعرض رسوم بيانية لحالة الاتصال وعدد الرسائل باستخدام Chart.js.
   - تعرض صفحة `/analytics` متوسط أزمنة الاستجابة بين استقبال الرسائل وإرسال الردود.
   - تعتمد هذه الصفحة على بيانات المسار `/metrics`، لذلك ينبغي إبقاؤه متاحًا في بيئة الإنتاج.
   - كما توفر صفحة `/dashboard` تحديثات فورية لحالة الاتصال وطول الطابور عبر WebSocket.
