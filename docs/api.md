# واجهات الاستخدام

يعتمد المشروع بشكل رئيسي على أوامر سطر الأوامر لتنفيذ المهام المختلفة، وتشمل ما يلي:

## إنشاء مساعد جديد
```bash
node src/scripts/createAssistant.js <organizationId>
```
ينشئ مساعدًا لـ OpenAI مرتبطًا بالمنشأة المحددة.

## رفع ملف مرجعي
```bash
node src/scripts/uploadFile.js <organizationId> <path/to/file>
```
يرفع ملفًا إلى حساب OpenAI ويُربَط بالمساعد الخاص بالمنشأة.

## تهيئة قاعدة البيانات
```bash
node src/initDb.js
```
ينشئ الجداول اللازمة لتخزين البيانات.

## تشغيل البوت
```bash
npm run whatsapp
```
يشغّل البوت ليتلقى الرسائل ويرد عليها حسب المساعد المربوط بالمنشأة.

## توليد اقتراحات الأسئلة المتكررة
```bash
npm run generate-faq
```
يحلل الرسائل الواردة ويملأ جدول `faq_suggestions` بأكثر الأسئلة شيوعًا.

## واجهة الإدارة عبر Express

يحتوي المشروع على لوحة تحكم بسيطة مبنية على Express لإدارة المنشآت والملفات
المرجعية. جميع المسارات محمية بتوثيق أساسي ويجب تمرير كلمة المرور المحددة في
`ADMIN_PASSWORD` للوصول إليها.

### المسارات المتوفرة

- `/` عرض جميع المنشآت المسجلة.
- `/org/new` إنشاء منشأة جديدة (يُستخدم `GET` لعرض النموذج و`POST` للحفظ).
- `/org/:id/assistant` إنشاء مساعد للمنشأة المحددة (`GET` يعرض النموذج و`POST`
  ينشئ المساعد).
- `/org/:id/upload` رفع ملف مرجعي للمساعد (`GET` لعرض النموذج و`POST` للرفع).
- `/users` إدارة المستخدمين وتغيير الأدوار (يتطلب صلاحيات المشرف).
- `/users/new` إضافة مستخدم جديد.
- `/users/:id/disable-2fa` تعطيل المصادقة الثنائية للمستخدم عند الحاجة.
- `/messages` البحث في جدول الرسائل مع خيار التصدير إلى CSV أو PDF.
- `/broadcast` إرسال رسالة جماعية لعدة أرقام أو لجميع عملاء منشأة.
- `/profile` عرض معلومات الحساب الحالي مع إمكانية تفعيل أو تعطيل 2FA (يتطلب جلسة دخول).
- `/profile/setup-2fa` إنشاء رمز QR وبدء تفعيل المصادقة الثنائية (يُمنع إذا كان 2FA مفعّلًا).
- `/profile/enable-2fa` حفظ السر بعد إدخال الرمز (يتطلب جلسة).
- `/profile/disable-2fa` مسح السر وإيقاف التحقق الثنائي (يتطلب جلسة).
- `/metrics` إرجاع مقاييس Prometheus لاستخدامها مع أدوات المراقبة.

يمكن للمشرف استخدام المسار السابق لإزالة رمز التحقق للمستخدم إذا فقد جهاز
المصادقة أو تعذر عليه تسجيل الدخول.

### الأدوار المتاحة

يملك كل مستخدم حقل `role` يمكن أن يكون `admin` أو `editor`. يمتلك المشرفون جميع الصلاحيات بينما يسمح دور `editor` بإنشاء المنشآت ورفع الملفات دون إدارة المستخدمين.

## سيناريوهات متقدمة

يمكن تشغيل البوت لأكثر من منشأة في وقت واحد. عند بدء `whatsappBot` أو
`worker` يُحمَّل جميع المنشآت التي تمتلك معرف مساعد كي يتم توجيه الرسائل
إلى المساعد المناسب تلقائيًا.

تُستعمل لوحة الإدارة لإضافة منشآت جديدة أو تعديلها وإنشاء المساعدات ورفع
الملفات الخاصة بكل منشأة. ومن خلال صفحة `/dashboard` يمكن مراقبة عدد
الرسائل في الطابور والاتصالات النشطة مع واتساب، مما يسهل إدارة عدة
منشآت ومتابعة أدائها من مكان واحد.

## تنبيهات Webhook

عند ضبط المتغير `WEBHOOK_URL` في ملف البيئة، يقوم العامل بإرسال طلب `POST`
إلى هذا العنوان بعد حفظ كل رسالة في قاعدة البيانات. يحتوي الطلب على
بيانات بسيطة عن الرسالة:

```json
{
  "sender": "user",
  "text": "مرحبا",
  "timestamp": 1712345678901
}
```

يمثل الحقل `timestamp` وقت استلام الرسالة بالمللي ثانية منذ 1970.
