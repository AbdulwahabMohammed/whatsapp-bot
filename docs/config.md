# متغيرات البيئة

لضمان تشغيل البوت بشكل صحيح يجب ضبط المتغيرات التالية في ملف `.env`:

| المتغير | مثال من `.env.example` | الوصف |
|---------|-----------------------|-------|
| `OPENAI_API_KEY` | `your-openai-key` | مفتاح الوصول إلى واجهة OpenAI |
| `PGHOST` | `localhost` | عنوان خادم قاعدة البيانات |
| `PGUSER` | `postgres` | اسم مستخدم قاعدة البيانات |
| `PGDATABASE` | `whatsapp_bot` | اسم قاعدة البيانات المستخدمة |
| `PGPASSWORD` | `password` | كلمة مرور المستخدم |
| `PGPORT` | `5432` | منفذ اتصال PostgreSQL |
| `REDIS_URL` | `redis://redis:6379` | عنوان خادم Redis المستخدم لطابور الرسائل (يجب أن يشير إلى خادم بإصدار 6.2.0 أو أحدث) |
| `WEBHOOK_URL` | `https://example.com/hook` | مسار اختياري لتلقي بيانات المحادثات |
| `ADMIN_PASSWORD` | `your-password` | كلمة المرور المطلوبة لدخول واجهة الإدارة |
| `ADMIN_PORT` | `3001` | المنفذ الذي تعمل عليه لوحة الإدارة |
| `SESSION_SECRET` | `change-me` | السر المستخدم لتوقيع جلسات لوحة الإدارة **ويجب تغييره في بيئات الإنتاج وإلا فلن يبدأ الخادم** |
| `LOG_LEVEL` | `info` | مستوى رسائل السجل (`info`، `error`، وغيرها) |
| `NODE_ENV` | `production` | تحديد بيئة التشغيل (`production` يعطل إخراج السجلات إلى الطرفية) |
| `MAX_RECONNECTS` | `5` | الحد الأقصى لمحاولات إعادة الاتصال بواتساب |
| `SUMMARY_MESSAGE_LIMIT` | `20` | عدد الرسائل في المحادثة قبل إنشاء ملخص |
| `BULK_MESSAGE_DELAY` | `500` | الفاصل بالميلي ثانية بين الرسائل الجماعية (من 0 وحتى 60000، يتحول إلى 0 تلقائيًّا عند تفعيل `FAST_DEV` ما لم يُحدَّد غير ذلك) |
| `DAILY_TOKEN_LIMIT` | `100000` | الحد الأقصى للتوكنات المسموح بها يوميًا لكل منشأة |
| `CONNECTION_RETRY_DELAY` | `5000` | الفاصل الزمني بين محاولات إعادة الاتصال بالواتساب (يتحوّل إلى 1000 ميلي ثانية في وضع `FAST_DEV` عندما لا يُضبط يدويًّا) |
| `DETECT_LANGUAGE` | `false` | اضبطه على `false` لتعطيل الكشف الآلي عن اللغة واستخدام لغة المنشأة مباشرةً |
| `FAST_DEV` | `true` | يفعّل وضع التطوير السريع الذي يغيّر القيم الافتراضية للمتغيرات التالية ما لم تُضبط يدويًّا |
| `RUN_MAX_RETRIES` | `60` | الحد الأقصى لمحاولات الاستعلام عن حالة الـ Threads (يصبح 20 تلقائيًّا عند تفعيل `FAST_DEV`) |
| `RUN_INITIAL_DELAY_MS` | `1000` | زمن الانتظار الأولي بين المحاولات بالميلي ثانية (يصبح 300 تلقائيًّا عند تفعيل `FAST_DEV`) |
| `RUN_MAX_DELAY_MS` | `5000` | الحد الأعلى للانتظار بين المحاولات (يصبح 1500 تلقائيًّا في وضع `FAST_DEV`) |
| `RUN_DELAY_GROWTH` | `1.2` | معامل زيادة التأخير بعد كل محاولة (يصبح 1.15 تلقائيًّا في وضع `FAST_DEV`) |

يتم تحميل جميع المنشآت تلقائيًّا من قاعدة البيانات دون الحاجة لأية متغيرات إضافية

يجب ضبط المتغيرات `PGHOST` و`PGUSER` و`PGDATABASE` و`PGPASSWORD` و`PGPORT`; إذ يتحقق التطبيق من وجودها قبل إنشاء الاتصال بقاعدة البيانات ويُلقي خطأً واضحًا مثل `Missing PGHOST environment variable` عند غياب أي منها.

قم بنسخ ملف `.env.example` إلى `.env` ثم عدل القيم بما يناسب بيئة النشر الخاصة بك.
**تأكد من استخدام مفتاح حقيقي في `OPENAI_API_KEY` قبل تشغيل الأوامر الإدارية**؛
يمكنك التحقق من صحة المفتاح من خلال [منصة OpenAI](https://platform.openai.com/account/api-keys)
وتجنب الاعتماد على القيم الافتراضية أو التجريبية.

يوفر المشروع أيضًا ملف `.env.dev.example` يُفعّل وضع `FAST_DEV` تلقائيًّا ويعطّل كشف اللغة،
مع تقليل فترات الانتظار الخاصة بالـ Threads وإعادة الاتصال بالواتساب لتسريع الاختبارات المحلية.
انسخ الملف إلى `.env` عندما ترغب في تشغيل البوت بسرعة في بيئة التطوير، ثم أعد القيم الافتراضية قبل النشر.

يمكن أيضًا تحديد تعليمات مخصصة لكل منشأة تُستخدم عند إنشاء المساعد الخاص بها، وذلك من خلال واجهة الإدارة أو بإدراجها يدويًّا في جدول `organizations`.
كذلك يتيح العمود `language` تحديد اللغة التي ستُستخدم في ردود المساعد لكل منشأة.

يُنشئ السكربت `initDb.js` جدولًا جديدًا باسم `usage_stats` لتخزين عدد التوكنات المستهلكة من قبل كل منشأة يوميًا. يحتوي هذا الجدول على الأعمدة `organization_id` و`tokens_prompt` و`tokens_completion` بالإضافة إلى تاريخ التسجيل.
كما يضيف الجدول `conversation_stats` لحساب زمن الاستجابة بين استلام الرسائل وإرسال الردود بالميلي ثانية.

يشمل المخطط كذلك جدولًا باسم `whatsapp_bots` يحتفظ بكل حساب واتساب مرتبط بمنشأة محددة عبر الحقول `organization_id` و`assistant_id` و`name` و`phone` و`status`. تُشغَّل هذه البوتات من لوحة التحكم، ويُعرَض رمز QR عند التشغيل عبر قناة WebSocket لربط الحساب. تُحفَظ بيانات الجلسة في مجلدات `auth-<botId>` بحيث يمكن إعادة تشغيل البوت دون إعادة المصادقة.

ينشئ `initDb.js` أيضًا المستخدم الافتراضي `admin` ويمكن إضافة مستخدمين آخرين بدور `admin` أو `editor` مع ربطهم بمنشأة عبر الحقل `organization_id` لتقييد الصلاحيات.

### الاسترجاع عند فشل تشغيل البوت أو فقدان الاتصال
1. أوقف البوت من لوحة التحكم ثم حاول تشغيله مجددًا للتأكد من أن الخدمة متاحة.
2. تحقق من عمل قاعدة البيانات وRedis وضبط قيمة `MAX_RECONNECTS` لمحاولات الاتصال التلقائي.
3. إذا استمرت المشكلة، احذف مجلد الجلسة `auth-<botId>` ليُطلب رمز QR جديد عند التشغيل التالي.
4. أعد تشغيل البوت وامسح رمز QR لإعادة المصادقة واستعادة الاتصال.
